# 🏥 SUPER ADMIN HOSPITAL MANAGEMENT SYSTEM\n\n## Overview\nA professional Super Admin Dashboard for managing multiple hospitals in a multi-tenant system. This system provides comprehensive control over hospital operations, admin management, and system-wide monitoring.\n\n## 🚀 Features\n\n### **Super Admin Dashboard**\n- **System Statistics**: Real-time overview of all hospitals and admins\n- **Activity Monitoring**: Track system-wide activities and events\n- **Multi-tenant Control**: Manage multiple hospitals from single interface\n- **Professional UI**: Modern, responsive design with intuitive navigation\n\n### **Hospital Management**\n- ✅ **Create Hospital**: Add name, location, contact info, subscription plan\n- ✅ **Feature Control**: Enable/disable specific features per hospital\n- ✅ **Status Management**: Activate/suspend hospital operations\n- ✅ **Soft Delete**: Recoverable deletion with data preservation\n- ✅ **Hard Delete**: Permanent removal from system\n- ✅ **Subscription Plans**: Basic, Premium, Enterprise tiers\n\n### **Hospital Admin Management**\n- ✅ **Create Admins**: Email + password + hospital assignment\n- ✅ **Access Control**: Activate/deactivate admin accounts\n- ✅ **Password Management**: Reset admin passwords securely\n- ✅ **Activity Tracking**: Monitor admin login activities\n- ✅ **Role Assignment**: Automatic admin role assignment\n\n### **System Monitoring**\n- ✅ **Real-time Statistics**: Hospital counts, admin status, subscription distribution\n- ✅ **Activity Timeline**: Recent system events and user actions\n- ✅ **Performance Metrics**: System health and operational insights\n- ✅ **Security Monitoring**: Access logs and authentication tracking\n\n## 🏗️ Architecture\n\n### **Backend Structure**\n```\nbackend/src/\n├── models/superAdmin/\n│   ├── hospital.model.js          # Hospital data model\n│   └── hospitalAdmin.model.js     # Hospital admin model\n├── controllers/superAdmin/\n│   ├── hospital.controller.js     # Hospital operations\n│   ├── hospitalAdmin.controller.js # Admin operations\n│   └── dashboard.controller.js    # Dashboard & monitoring\n├── routes/superAdmin/\n│   ├── hospital.routes.js         # Hospital endpoints\n│   ├── hospitalAdmin.routes.js    # Admin endpoints\n│   └── dashboard.routes.js        # Dashboard endpoints\n└── middleware/\n    └── superAdminAuth.js          # Authentication middleware\n```\n\n### **Frontend Structure**\n```\nfrontend/src/\n├── components/superAdmin/\n│   ├── SuperAdminLayout.jsx       # Main layout component\n│   ├── SuperAdminSidebar.jsx      # Navigation sidebar\n│   └── SuperAdminNavbar.jsx       # Top navigation bar\n├── pages/superAdmin/\n│   ├── SuperAdminDashboard.jsx    # Main dashboard\n│   ├── HospitalManagement.jsx     # Hospital CRUD operations\n│   ├── HospitalAdminManagement.jsx # Admin management\n│   └── SystemActivity.jsx         # Activity monitoring\n└── pages/auth/\n    └── SuperAdminLogin.jsx        # Secure login page\n```\n\n## 🔗 API Endpoints\n\n### **Dashboard Endpoints**\n- `GET /api/v1/super-admin/dashboard/stats` - System statistics\n- `GET /api/v1/super-admin/dashboard/activity` - Recent activities\n- `GET /api/v1/super-admin/dashboard/settings` - System settings\n\n### **Hospital Management**\n- `POST /api/v1/super-admin/hospitals` - Create hospital\n- `GET /api/v1/super-admin/hospitals` - List all hospitals\n- `GET /api/v1/super-admin/hospitals/:id` - Get specific hospital\n- `PUT /api/v1/super-admin/hospitals/:id` - Update hospital\n- `PATCH /api/v1/super-admin/hospitals/:id/status` - Update status\n- `PATCH /api/v1/super-admin/hospitals/:id/features` - Update features\n- `PATCH /api/v1/super-admin/hospitals/:id/soft-delete` - Soft delete\n- `DELETE /api/v1/super-admin/hospitals/:id` - Hard delete\n\n### **Admin Management**\n- `POST /api/v1/super-admin/hospital-admins` - Create admin\n- `GET /api/v1/super-admin/hospital-admins` - List all admins\n- `GET /api/v1/super-admin/hospital-admins/hospital/:hospitalId` - Get admins by hospital\n- `PATCH /api/v1/super-admin/hospital-admins/:id/status` - Update status\n- `PATCH /api/v1/super-admin/hospital-admins/:id/reset-password` - Reset password\n- `DELETE /api/v1/super-admin/hospital-admins/:id` - Delete admin\n\n## 🔐 Security Features\n\n### **Authentication & Authorization**\n- JWT-based authentication with super_admin role verification\n- Secure password hashing with bcrypt\n- Protected routes with middleware validation\n- Session management and token expiration\n\n### **Data Protection**\n- Input validation and sanitization\n- SQL injection prevention\n- XSS protection\n- CORS configuration\n- Rate limiting on sensitive endpoints\n\n### **Access Control**\n- Role-based access control (RBAC)\n- Super admin privilege verification\n- Hospital-specific admin isolation\n- Activity logging and audit trails\n\n## 🎨 User Interface\n\n### **Design Principles**\n- **Professional**: Clean, modern design suitable for enterprise use\n- Super Admin credentials\n\n### **Backend Setup**\n1. Navigate to backend directory\n2. Install dependencies: `npm install`\n3. Configure Firebase credentials\n4. Start server: `npm start`\n\n### **Frontend Setup**\n1. Navigate to frontend directory\n2. Install dependencies: `npm install`\n3. Configure API endpoints\n4. Start development server: `npm run dev`\n\n### **Access Super Admin**\n1. Visit `/super-admin/login`\n2. Enter super admin credentials\n3. Access dashboard at `/super-admin/dashboard`\n\n## 🔧 Configuration\n\n### **Environment Variables**\n```env\n# Backend\nPORT=5000\nJWT_SECRET=your_jwt_secret\nSERVICE_ACCOUNT_PATH=path_to_firebase_credentials\nCORS_ORIGIN=http://localhost:3000\n\n# Frontend\nVITE_API_URL=http://localhost:5000/api/v1\n```\n\n### **Firebase Setup**\n1.
